## 먼저 구분할 용어

| 용어 | 쉬운 뜻 | 우리 구조에서의 예 |
|---|---|---|
| Control Plane | 누가 무엇을 할 수 있는지 정하는 통제 영역 | Spring의 권한·예산·정책 판단 |
| Execution Layer | 허용된 작업을 실제로 수행하는 영역 | FastAPI의 검색·모델 호출 |
| Tenant | 서로 데이터가 섞이면 안 되는 고객 조직 | 로펌 A와 로펌 B |
| Case Scope | 이번 요청에서 접근 가능한 사건 범위 | 로펌 A의 사건 1234만 허용 |
| memvid | 자료와 검색용 색인을 파일에 보관하는 부품 | case_1234.mv2 |
| Embedding | 문장 의미를 비교하기 위한 숫자 벡터 | 문서와 질문을 같은 모델로 변환 |
| Context | 이번 모델 호출에 실제로 넣는 참고 자료 | 선택한 근거 문단과 출처 |
| Reservation | 사용 전 예산에서 잠시 확보하는 금액 | 최종 모델 호출 전 예상 비용 예약 |
| Settlement | 실제 사용을 확인해 비용을 확정하는 처리 | 공급자 usage와 비용 원장 대조 |
| Hard Cap | 더 진행하면 안 되는 강제 상한 | 최대 비용·단계·시간·출력량 |
| Human-in-the-loop | 중간에 사람이 검토·피드백하는 과정 | 변호사가 초안과 출처 확인 |
| Audit | 나중에 누가 무엇을 했는지 확인할 기록 | 요청 ID·정책 사유·작업 상태 |

## 가상 요청 하나로 따라가기

다음은 구현 목표를 이해하기 위한 예시이며 실제 실행 기록이 아닙니다.

1. 로펌 A의 변호사가 사건 1234의 보증금 반환 상담을 정리해 달라고 요청합니다.
2. Spring은 로그인뿐 아니라 해당 사건의 담당 권한도 확인합니다. 사건 ID를 안다고 접근을 허용하지 않습니다.
3. 입력의 위험 신호와 개인정보를 처리하고 현재 세션이 제한되었는지 확인합니다.
4. 예상 작업·모델·예산·시간 한도를 정하고 내부 요청을 보냅니다.
5. Python도 서명·만료·사건 범위를 확인합니다. 서버 매핑으로 사건 파일을 고릅니다.
6. 필요한 임베딩을 준비하고 memvid에서 근거를 찾습니다. 외부 임베딩이 유료라면 그 호출부터 승인·예약합니다.
7. 검색 문단에서 출처·날짜·금액·상충 진술을 보존합니다. 추가 정제가 유용할 때만 승인된 모델을 호출합니다.
8. 사람 검토가 필요하면 초안 버전과 대기 상태를 저장하고 연결·파일 핸들을 해제합니다.
9. 피드백 후 재개할 때 검토자 권한·자료 버전·예산을 다시 확인합니다.
10. 최종 모델의 JSON·출처·내용을 확인하고 Spring의 검증 후 검토용 보고서로 저장합니다. 이미 실행한 유료 단계는 실패 여부와 별개로 사용량을 정산합니다.

## 가장 헷갈리는 다섯 가지

**로그인과 사건 권한은 다릅니다.** 로그인은 누구인지 확인하는 일이고, 사건 권한은 그 사람이 이번 자료를 읽어도 되는지 확인하는 일입니다.

**파일 분리와 완전한 보안은 다릅니다.** 파일을 나눠도 잘못된 경로 매핑, 공유 캐시, 로그, 백업에서 다른 사건 자료가 나올 수 있습니다.

**검색과 생성은 다릅니다.** memvid 검색은 관련 근거를 고르는 일입니다. LLM 생성은 그 근거를 참고해 새 문장을 쓰는 일입니다. 근거가 있어도 생성 내용이 틀릴 수 있습니다.

**비용 예약과 실제 비용은 다릅니다.** 남은 예산이 100인데 요청 두 개가 각각 80을 승인받으면 합계가 160이 될 수 있습니다. 잔액 검사와 예약을 하나의 원자적 처리로 묶어야 합니다. 숫자는 학습용 예시입니다.

**타임아웃과 미실행은 다릅니다.** 응답을 못 받았어도 공급자가 처리했을 수 있습니다. 미확정 상태로 추적하고 실제 사용량을 대조합니다.

## 도식 읽는 순서

- 초록 상자: Spring의 통제·정책 책임을 찾습니다.
- 노란 마름모: 어떤 조건에서 예·아니오로 갈리는지 읽습니다.
- 빨간 상자: 무엇을 중단하고 어떤 기록을 남기는지 확인합니다.
- 파란 상자: 자료·상태·검색과 검증의 흐름을 읽습니다.
- 주황 상자: 모델 실행과 비용 승인 지점을 연결해 봅니다.

S6 감사와 C6 정산은 맨 끝에서 한 번만 하는 검사가 아닙니다. 실행 전후 전체 수명에 걸쳐 적용됩니다. 상세도의 정상 경로 외에도 인증·파일 권한·단계 승인 실패는 실행을 거부하도록 구현해야 합니다.
